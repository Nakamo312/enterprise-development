# Clinic Management System

## Архитектурный дизайн

#### **Основные принципы:**
- **Многослойная архитектура** (Clean Architecture)
- **Разделение ответственности** по проектам
- **Микросервисный подход** для асинхронных операций
- **Контейнеризация** через .NET Aspire

#### **Ключевые паттерны:**
- Repository Pattern для доступа к данным
- Service Layer для бизнес-логики
- DTO Pattern для передачи данных между слоями
- Publisher/Subscriber для асинхронной коммуникации

### Доменная модель

#### **Основные сущности:**
1. **Patient (Пациент)**
   - Личные данные: ФИО, паспорт, дата рождения
   - Контактная информация: адрес, телефон
   - Медицинские данные: группа крови, резус-фактор, пол
   - Связь: множество приемов (Appointments)

2. **Doctor (Врач)**
   - Профессиональные данные: специализация, стаж
   - Личные данные: ФИО, паспорт, год рождения
   - Связь: специализация, множество приемов

3. **Specialization (Специализация)**
   - Наименование специализации (терапевт, хирург и т.д.)
   - Связь: множество врачей

4. **Appointment (Прием)**
   - Временные данные: дата и время приема
   - Организационные: номер кабинета, признак повторного приема
   - Связи: пациент, врач

#### **Перечисления:**
- **BloodGroup**: A, B, AB, O
- **Gender**: Male, Female
- **RhFactor**: Positive, Negative

### Системная интеграция

#### **1. Blazor WebAssembly Клиент**
- **Технология**: Blazor WebAssembly 8.0
- **Взаимодействие**: HTTP REST API
- **Особенности**:
  - Компонентная архитектура с переиспользуемыми компонентами
  - Интеграция с MudBlazor для UI компонентов

#### **2. ASP.NET Core Web API**
- **Технология**: ASP.NET Core 8.0
- **Архитектура**:
  - Generic CRUD контроллеры (CrudControllerBase)
  - Dependency Injection для управления зависимостями
- **Функционал**:
  - RESTful API для всех сущностей
  - Аналитические запросы через AnalyticController
  - Валидация через Data Annotations
  - Автоматическое маппинг через AutoMapper

#### **3. Сервисный слой (Application)**
- **Структура**:
  - Generic сервисы (BaseCrudService)
  - Специализированные сервисы для каждой сущности
  - DTO для передачи данных между слоями
- **Особенности**:
  - Разделение Create/Update/Response DTO
  - Валидация бизнес-правил
  - Транзакционность операций

#### **4. Инфраструктурный слой**
- **База данных**: PostgreSQL + Entity Framework Core 8.0
- **Подходы**:
  - Code-First с миграциями
  - Fluent API для конфигурации сущностей
  - Repository Pattern с двумя реализациями:
    - Repository (EF Core для продакшена)
    - InMemoryRepository (для тестирования)
- **Data Seeding**:
  - EfDataSeeder для PostgreSQL
  - InMemoryDataSeeder для тестов

#### **5. RabbitMQ Интеграция**
- **Назначение**: Асинхронная обработка событий
- **Архитектура**:
  - **Producer**: Отправляет сообщения при создании сущностей
  - **Consumer**: Обрабатывает сообщения в фоновом режиме
- **Формат сообщений**: JSON с оберткой MessageEnvelope
- **Типы сообщений**: EntityCreatedResponse для разных сущностей

#### **6. Генератор тестовых данных**
- **Тип**: Консольное приложение
- **Функционал**:
  - Генерация данных для всех сущностей
  - Управление зависимостями между сущностями
  - Интерактивное подтверждение создания
  - Трекинг ID для связывания сущностей

#### **7. Оркестрация через .NET Aspire**
- **Назначение**: Упрощение разработки и развертывания
- **Функции**:
  - Service Discovery для автоматического нахождения сервисов
  - Health Checks для мониторинга состояния
  - Конфигурация зависимостей (PostgreSQL, RabbitMQ)
  - Единая точка запуска всей системы

### Бизнес-логика и аналитика

#### **Аналитические запросы:**
1. **Врачи с большим опытом** - фильтрация по стажу ≥ 10 лет
2. **Пациенты врача** - получение всех пациентов конкретного врача
3. **Статистика повторных приемов** - анализ за последний месяц
4. **Активные пациенты** - пациенты старше 30 лет с >1 врача
5. **Расписание кабинета** - приемы в текущем месяце по кабинетам

#### **Валидация:**
- Серверная: Data Annotations, кастомные атрибуты (EnumRangeAttribute)
- Клиентская: Blazor Forms Validation
- Бизнес-правила: проверка в сервисном слое

### Взаимодействие компонентов

#### **Синхронный поток (CRUD операции):**
Пользователь → Blazor Client → HTTP REST → ASP.NET API
→ Application Service → Repository → PostgreSQL
← Response ← JSON ← DTO ← Business Logic ←

#### **Асинхронный поток (События):**
Создание сущности → Producer → RabbitMQ → Consumer
→ Фоновая обработка → Логирование/Уведомления
